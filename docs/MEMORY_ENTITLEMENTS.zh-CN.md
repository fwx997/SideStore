# Henge 内存授权与安装兼容性

Henge 的原始安装包包含增加内存上限和扩展虚拟寻址请求，但 .36 的
SideStore 最终签名只从描述文件取授权项。自定义授权项没有传给签名器；
描述文件未列出的内存请求会消失。保存续签信息时再次取描述文件，也会
丢失这些请求。

`.41` 已因实机反馈撤回：默认附加权限把 Entitlement 对象当成值，导致
直接安装 LiveContainer2 报 `must be a Boolean`；该版又把描述文件未授权的
内存请求写进签名，与 Henge 的 `0xe8008015` 拒绝安装相符。

修复将三个默认内存请求改为真正的 Boolean，默认值不再覆盖原包的关闭值、
用户的关闭/删除选择或续签缓存。主程序的默认请求不传给扩展。

主程序和每个扩展的自定义授权项仍按最终包标识传给 SideSign。增加内存上限
只有在该可执行文件的描述文件明确授权为 Boolean true 时才会写入：

- com.apple.developer.kernel.increased-memory-limit

描述文件缺少这项权限或值为 false 时，签名器移除它并记录原因。扩展虚拟寻址、
额外调试内存等其他授权项继续按原描述文件规则处理。恢复原有能力申请流程，
仅向 Apple 请求当前账户类型允许的能力；不扩大免费账户能力列表。应用标识和
团队标识仍取自描述文件，不修改 Apple 签署的描述文件。

签名完成后重新读取每个可执行文件，核对过滤后的内存授权项；丢失、变值或
意外出现未授权内存权限都会报告失败。续签缓存保存实际签名，防止旧缓存
或默认值复活已移除的请求。真实设备安装仍需复测。

界面的请求开关不代表 Apple 已授权。现有导出的 Henge 描述文件不含这项权限，
这种情况下新包应能避免 `.41` 引入的不匹配签名，但 Extra memory 仍可为 Off；
要变成 On，需取得确实授权该权限的有效描述文件。不能靠强行添加签名字段保证
额外内存生效，也不能保证 8 GB 虚拟机可启动。

## 构建

SideSign 子模块仍固定在 752d1ef602aa792a432ffa1e71646dc1ecf7363c。
修复以 scripts/patches/sidesign-memory-entitlements.patch 随仓库保存，
不另建依赖仓库。make build 和构建测试目标自动应用补丁。直接使用
Xcode 前先运行：

    git submodule update --init Dependencies/SideSign
    python3 scripts/apply_signing_patches.py

补丁已应用时不会重复修改；上游源码不兼容时停止构建，不强制覆盖。

## 验证

    python3 -m unittest discover -s scripts/tests -p test_memory_entitlements.py -v

回归直接编译生产默认值、权限/能力模型、签名器及 SideStore 的申请、选择和缓存方法，
以不使用真实证书的签名后端替身记录实际发出的 XML。覆盖原始包、已丢失
权限的缓存包、主程序与扩展隔离、关闭/删除、包标识变更、五轮续签、
签名后丢失权限以及非法数据类型。新增直接安装的真实默认值、描述文件授权缺失/
关闭/开启、默认值与关闭/删除选择冲突、主程序/扩展不同授权、续签时授权丢失、
签名器意外注入权限和账户能力过滤场景。

这些检查验证签名传递与续签行为；iPadOS 是否接受安装、设备是否提供额外
内存，以及 Henge 能否启动，还需真机验证。Extra memory: On 也不保证可以
分配 8 GB。首次设备回归先使用 4 GB，并检查重签后导出的 IPA 和下一轮续签。
